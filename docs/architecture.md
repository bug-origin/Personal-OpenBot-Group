# 架构与接口

```text
Tauri / React 客户端
      ↕ HTTP + 认证 WebSocket
Fastify / SQLite ── 每 Bot 独立注意力判断 → 主会话 → 异步 Worker 调度
      ↕ 独立凭据的 Bridge WebSocket
Node.js 本地 Bridge
      ↕ stdio JSON-RPC（按需启动）
Codex app-server / Claude Code stream-json
```

桌面安装包自带 Node.js、后台服务和本机 Bridge。界面启动时通过唯一的 Tauri `local_service` 命令取得本机连接；随机凭据由后台生成并以 0600 权限持久化，界面无需展示或存储令牌。服务只监听 127.0.0.1，优先复用上次端口，冲突时自动另选端口；同一数据目录禁止重复启动。原生宿主持有后台的父进程管道。关闭窗口隐藏界面并保留后台；托盘提供打开与退出，macOS Dock 可恢复窗口。明确退出或管道关闭时先停止 Bridge、关闭数据库，再结束服务。后台异常退出后界面自动重启连接，不自动重放已派发任务。源码开发启动器仍负责开发服务，桌面调试通过继承的环境直接复用该连接。

`apps/desktop` 负责交互；`apps/server` 负责持久身份、消息、路由、任务、审批和协作预算；`apps/bridge` 拥有本地执行能力；`packages/shared` 定义实体与执行协议。Tauri 不开放 shell / 文件系统权限给群消息。

## 身份与数据边界

Bot、群组与单聊直接归当前所有者管理，不再使用额外的命名容器。迁移 `009` 移除旧版容器表及关联字段，保留身份、成员、消息、任务和原生会话。

当前为同机单所有者模型，客户端令牌表示当前所有者。Bridge 使用独立令牌，浏览器 Origin 不得连接 Bridge 通道。所有者通过认证 API 绑定 Bot 与设备；群消息无法修改绑定、Provider 配置或审批策略。

Bridge 声明本机 CLI 与认证配置就绪的 Provider 可用。Codex 使用 app-server 的 `account/read` 查询有效 Provider 的 `requiresOpenaiAuth`；自定义 Provider 不要求 OpenAI 登录时，不受 `codex login status` 拦截。检查不创建会话或调用模型，服务连通性仍以真实执行为准。当前实现 Codex 与 Claude Code 两个本地适配器。进程启动时移除 OpenBot 和 DeepSeek 平台凭据，保留 Provider 自身的授权与配置。只读沙箱限制写操作，但不代表读取范围仅限 cwd；不应将其描述为完整的文件保密隔离。

服务仍只监听 loopback；远程 Bridge 与多人访问需要独立的配对、设备授权、网络和所有者身份校验，当前不提供。

## 协议

| 方法         | 路径                              | 行为                                                                                |
| ------------ | --------------------------------- | ----------------------------------------------------------------------------------- |
| GET          | `/health`                         | 无凭据健康检查                                                                      |
| GET          | `/api/snapshot`                   | 已认证所有者的 Bot、群组、消息、任务、Bridge 概况、审批与智能协作状态，不含任何密钥 |
| POST / PATCH | `/api/groups` / `/api/groups/:id` | 创建/编辑群组与成员                                                                 |
| POST         | `/api/bots`                       | 创建身份并自动连接唯一可用 Agent；多设备时可在同次请求指定 bridgeId                 |
| POST         | `/api/bots/:id/bind`              | 仅绑定 bridgeId；执行中拒绝更改绑定                                                 |
| POST         | `/api/messages`                   | 以消息 UUID 为幂等键保存消息并触发路由                                              |
| POST         | `/api/chains/:id/stop`            | 记录停止标记、取消排队项、请求当前执行中断                                          |
| POST         | `/api/approvals/:id`              | 当前任务的一次 accept / decline 决策；拒绝已过期或重复审批                          |
| POST         | `/api/native-requests/:id/reply`  | 回答当前原生问答或权限请求，校验回答、有效期及原始任务租约                          |

`/events` 使用首帧 `{type:"auth",token}`，返回 ready 后推送 invalidate。客户端重新拉快照，断线退避重连；全量快照适用于小规模本地版本，大历史量需要分页与增量同步。

`/bridge` 的首帧为 hello，携带独立令牌、设备 ID 和 Provider 能力。服务端心跳检测连接，拒绝重复在线设备 ID。服务发出 run / cancel / approval；Bridge 返回 session / started / progress / activity / heartbeat / report / result / approval。activity 只记录原生工具生命周期和执行者公开 commentary，不读取模型隐藏推理；heartbeat 是每个执行租约的存活信号，report 区分普通进展、里程碑和阻塞。

每个任务都有随机 `leaseId`。只有当前绑定设备、任务、lease 和仍在执行中的状态完全匹配，事件才生效；断线后的迟到输出、重复完成事件不能写入群组或触发新调用。

## 每 Bot 对话协调与执行

默认入口使用 `createAttentionModel`、`createCoordinatorModel` 与 `BotCoordinator`，不创建群级路由模型。人类群消息在消息事务内写入每位成员的持久收件箱；Bot 群消息也投递给其他成员，不回投发送者。每个 Bot 全局串行处理自己的事件，不同 Bot 并行。

普通群消息先调用独立、无工具的注意力模型。输入仅包含自己的身份与职责、当前消息和回复目标、截至来源消息的近期群聊、群内成员与任务归属；输出严格限定为 `{"wake":true}` 或 `{"wake":false}`。false 只保存原消息与判断记录，不进入主会话、不执行工具、不创建任务或写入长期记忆。true 进入主会话，但不要求发言。私聊、直接 @ 自己、明确回复自己的消息、本人任务完成与停滞事件跳过判断。人类与 Bot 消息使用相同关联规则；具备能力不等于应该接管同事的工作。

`attention_decisions` 保存输入快照、结果、尝试次数及错误。失败最多自动尝试三次，重启沿用剩余尝试次数；失败显示在来源消息下，可单独重试该 Bot，不被当成 false 或默认放行。已提交的判断重启后复用；已有主会话与工具调用按原机制恢复，不重新判断或重复执行。设置页可单独选择同服务的注意力模型，留空跟随对话模型，但调用与上下文始终独立；私聊不产生注意力调用。

Bot 可以在群内 @ 同事请求协助或回传结果，也可由同事的注意力判断接收未提及自己的相关消息。实际进入主会话的 Bot 消息唤醒才消耗 `bot_wakes` 预算，判断与预算扣减原子提交；被动扇出和 false 不计费。协作受链的停止标记、调用上限和 Bot 回复深度共同限制，避免无限互相回复。

主会话使用 DeepSeek Function Calling；当前关闭思考模式。平台校验参数、成员、任务归属、要求版本、预算和原生权限。模型可以启动、查询、调整、停止、继续及验收工作，也能按引用恢复消息、任务和执行记录。模型拥有调度工具，文件与命令交给 Worker。

任务与执行分离：`tasks` 保存目标，`task_workers` 保存 Provider、资源及验收状态，`worker_runs` 保存逐次租约、设备、原生会话、版本、真实输出和结束状态。同一 Bot 默认最多 2 个执行、同设备最多 4 个；相同、父子或未知资源保守串行。资源占用不是文件锁或文件系统隔离。

任务先分配持久工作管道，再进入执行队列。管道归 Bot 与当前对话所有；同一任务调整或返工继续原管道，明确相关的下一项任务可传 pipelineId 复用，独立目标新建。按目录相同不会自动合并。每个管道一次只运行一项工作，待验收仍占用；未知执行未核实前不能通过新任务绕过。

原生会话按管道、Provider、设备映射；首次切换执行工具新建并明确交接，切换回来恢复对应的历史会话。复用管道中的新任务发送完整新要求，不沿用上一任务的要求接收游标。Worker 返回后进入 reviewing，由主会话对照要求及证据验收或继续处理。执行过程不阻塞对话，Worker 不直接向群发布结果。完整流程、工具及边界见 [持续工作设计](super-agent.md)。

`brain.ts`、`dialogue.ts` 和 `Conversations` 的群路由／JSON 单次对话接口仍保留供旧调用方和回归测试使用；下文提及旧行为时以默认主会话流程为准。未配置 DeepSeek 时保留明确 @ 直接执行。

## 停止与故障

协作链携带 correlationId，默认最多 6 轮、12 次入队调用。达到限制后阻断新唤醒；手动停止也先写入停止标记，因此完成事件与停止竞争时不会启动下一位 Bot。

停止先将运行任务置为 cancelling，Bridge 调用原生 interrupt；收到真实结果后再置为 cancelled 或保留已实际完成的结果。Bridge 的取消兜底会终止本次原生进程。若服务端迟迟收不到确认，会断开该 Bridge 并把任务标为结果未知，不把超时伪装成已成功取消。

连接中断的已派发任务不自动重跑，避免重复副作用；尚未派发的队列在重新连接后继续。服务重启保留 Bot、绑定、消息、会话与队列，运行状态清为离线，未确认执行标为失败。

原生请求带 requestId 并绑定原始任务及 leaseId。认证 Bridge 的 interaction 事件创建系统拥有的群消息卡片；native_reply 只回到当前等待中的原生进程，不经对话模型或任务入队。Codex 支持原生问答、命令/文件审批及 turn/session 权限申请；Claude 支持 AskUserQuestion 与逐项工具审批。服务端校验回答所属问题、选项、重复项和授权范围，Bridge 再次校验并使用保存的原始操作参数。停止、断线、原生撤回或服务重启使未回答请求失效。多人版本必须把审批内容限制到 Agent 所有者，不能直接复用当前共享令牌授权模式。

## 迁移与已知范围

`001_initial.sql` 定义基础身份、群组、消息、任务；`002_runtime.sql` 增加绑定、原生会话、协作链、任务租约、路由记录和审批。`003_dialogue.sql` 增加对话收件箱、对话摘要、任务快照和版本化变更。迁移启动时幂等应用，SQLite 启用外键与 WAL。

`006_native_requests.sql` 持久保存原生请求及系统消息关联；相同回答哈希用于幂等提交，秘密回答在历史中掩码。任务离开 running 状态时由数据库触发器撤销未回答请求。

远程配对、多人权限、超大历史同步、群组持续资源共享与撤销尚未实现。自动测试使用临时适配器；真实验证脚本另行显式调用 Provider。

## 持续对话与任务分支

主会话近期上下文包括群消息、来源记忆、本人任务和群内工作归属；完整消息、任务和长结果按 ID 与偏移量检索。旧版 Bot×群组摘要保留为检索辅助。对话历史与任务状态均在本地 SQLite 中持久保存，模型 API 不负责保存主会话。

`coordinator_turns` 保存消息和模型响应，`coordinator_calls` 保存逐个工具调用结果。模型请求先落库，工具的数据库副作用与结果记录原子提交；最终回复与收件箱确认也在同一事务完成。重启恢复未完成事件时不重复已经提交的调度操作。

运行中变更先保存原始请求并使用 expectedVersion 防止覆盖，停止旧执行，收到结果后用新 lease 续接。原生 started 确认推进要求接收游标。停止撤销待续接变更，防止任务复活；未知执行不会自动重跑。

Worker 原始输出保存后，持久完成事件交给主会话。主会话必须依据事实验收或安排返工；只用文字声称完成不能将任务标为 completed。调用失败时保留原始结果与待验收状态，避免把进度重建成结论。

TaskWatchdog 维护每 Bot 的任务台账与 task_health，区分排队、等待设备、授权问答、执行、受阻、进展停滞、心跳超时、待验收及结果未知。每十五秒的执行心跳不刷新进展时间；每分钟检查，五分钟无活动才复核，再用九十秒心跳阈值区分 stalled 与 unresponsive。它只维护观察事实、生成去重事件，不直接失败、终止或自动重跑任务。

worker_reports 持久保存 Worker 的公开进展，按当前任务租约校验、去重与汇总。普通进展通常每分钟至多通知所属 Bot 一次，里程碑和明确阻塞可立即通知；输出片段和心跳不逐条触发模型。普通进度与里程碑事件强制只读且不能发布聊天或写记忆；完成／停止或更换租约后，迟到汇报及仍在等待模型返回的旧处理都会丢弃。阻塞问题由 Bot 决定是否需要问所有者，结果仍独立验收。

Bot 以尊重、诚实、善意和同理心回应用户。面向自己或全群的招呼、感谢、告别和情绪关切属于相关交流，例如“大家好”应友好接住；点名同事或同事之间的客套不引起抢答或循环回礼。对外不播报任务接收、管道安排、监控和等待，不叙述沉默，也不采用机械字数限制。有意义的社交回应、有用答案、必要决策和核实后的交付都可以发言。

新增认证 API：

- `DELETE /api/groups/:id`：删除普通群组及其聊天、任务、管道、审批、群内记忆与协调记录。保留数字员工、单独聊天和 Bot 长期记忆，长期记忆仅解除已删除来源消息的引用；有执行、排队、待验收任务或正在处理的消息时返回冲突提示。删除在同一事务中完成，不能用于移除单独聊天。
- `POST /api/messages/:id/retry`：默认协调器重试失败的人类或 Bot 消息，可指定 `botId`；保留成功成员与已提交工具结果，不重复派发。旧版通道仍只补投尚未投递的人类消息。
- `GET /api/tasks/:id/status`：任务快照及事实摘要。
- `POST /api/tasks/:id/change`：`{instruction, expectedVersion}`，保存要求变更。
- `POST /api/tasks/:id/stop`：停止单个任务；原有 chain stop 同时阻断后续协作。
- `POST /api/tasks/:id/resume`：所有者明确请求恢复结果未知的中断任务，传入 `{instruction, expectedVersion}`。保留原任务与原生会话，先核实产物再继续；不伪造群聊消息，不自动重跑。

桌面源码启动（`npm run desktop`）关闭服务端源码监听重启，避免修改代码打断正在运行的工作。服务端代码更新须在任务空闲时显式重启；浏览器开发（`npm run dev`）仍使用源码监听。

默认采用原生受限策略，额外操作需通过明确的原生审批。文件占位、worktree、合入队列与跨终端授权不在本次实现范围。原生会话历史由各自 Provider 管理，日常对话保存在 OpenBot；手动在 Codex 继续任务不会同步回对话收件箱。

群聊接手、查询进度、变更、停止和异常回退统一采用日常表达。编号、版本、队列和执行实例仅供内部协调，不进入 Bot 回复；对话模型也必须遵守这一输出边界。概览不显示版本或协作轮次，原始字段仍可用于认证诊断接口。

Bridge 默认不限制执行总时长，只有显式的 `OPENBOT_TASK_TIMEOUT_MS > 0` 才启用总时长上限。达到限制的执行标为 failed 并记录自动中断原因；手动取消才使用 cancelled。

## 精准传递原生会话输入

新工作不复制整个近期群聊；对话协调提供简短工作说明及最多四条必要引用，服务端校验引用属于本群且不晚于来源消息，自动保留明确回复的引用。选中的原文保留完整内容。原生 turn/start 使用简洁正文，不再发送包含 Bot、群组、租约、完整修改历史的 JSON 信封。身份与协作规则在 thread/start 时设置一次。

`004_session_delivery.sql` 记录 task + native thread 的 accepted_version。恢复会话只发高于该游标的新增要求，不重发原始工作说明与已确认的补充要求。原生 started 或 completed 事件推进游标，过期 lease 无效。尚未确认收到的初始要求保留必要背景；未知执行不会自动重跑。

明确继续已结束的同一件工作时，通过 continue 动作恢复原生 thread，使用新的人类请求协作链与新 lease；独立工作仍新开会话。纯聊天或询问已有结果不启动执行。完成事件保存原始来源消息与关联链，后续续接不会改变旧结果的回复归属。

`013_task_pipelines.sql` 为历史协调任务分别建立独立管道，迁入已知的原生会话映射，并新增健康台账与汇报存储。管道不会跨 Bot、对话或设备共享原生会话；任务、消息和记忆保留。

## Claude Code 适配

Bridge 按当前 Worker 的 Provider 选择 Codex app-server 或 Claude Code stream-json。两者使用相同任务协议、租约、队列、精简输入和动态渲染说明。Claude 默认允许 Read、Glob、Grep，Bash / Edit / Write 必须经过原生审批，AskUserQuestion 转为原生问答卡。使用 restricted / safe-mode 和空 MCP 配置，禁止原生子 Agent、用户插件及项目 hooks。复用 CLI 自身登录，不把平台密钥传给它。

Claude 新工作使用独立 UUID 会话，同工作通过明确 session ID 恢复，不使用“最近会话”。收到原生 init 才保存会话 ID，收到当前用户输入确认才推进要求版本。只转发文本、工具活动和最终结果，跳过隐藏推理与子 Agent 输出；无 result 或恢复到其他会话视为失败。取消先发送 SIGINT，再按时限结束所属进程组，等待真实退出后才返回结果。工具能力边界及真实验证方式见 [Claude 接入](claude.md)。

## 设备绑定与动态资源

Bot 只保存身份、Provider 和所属设备，群组只组织对话；API、任务快照和客户端均不保存固定项目路径。新原生进程由本地执行层选择系统启动位置，恢复会话沿用原生上下文。Agent 根据用户提供的文件、项目或其他资源引用动态定位目标，路径不明确时询问，需要额外权限时通过原生卡片申请。操作审批中的位置与具体文件详情仍保留，方便用户判断授权范围。

创建 Bot 时自动选择唯一可用且 Provider 匹配的设备，直接保存关联并显示在线。多台设备同时可用时在创建表单内选择；服务端拒绝歧义及失效选择，失败不会残留身份。暂时没有可用设备时保留未连接身份，之后设备接入会自动连接匹配的 Bot。已有设备关联不会因其他设备接入被覆盖，原设备恢复后自动上线。「查看 Agent 状态」用于诊断，单设备日常使用不再提供独立绑定步骤。

Claude 保持 restricted、safe-mode 和逐项命令/写入审批，并通过原生 `--add-dir` 纳入所在文件系统根路径，避免内部启动位置限制资源定位。默认只读工具可以访问系统账户有权读取的资源；这不是按项目隔离的文件保密边界。

`007_device_bindings.sql` 移除旧的路径绑定数据和任务中的路径列，保留设备关联、消息、任务和原生会话 ID。迁移按版本只应用一次，避免已删除结构在重启时重新建立。历史迁移文件保留用于旧版本数据库升级。

`008_direct_chats.sql` 为每个 Bot 提供一个持久的一对一会话，以独立会话组保存消息、任务、审批与对话记忆。直接聊天消息只路由至关联 Bot，不经过群组自动分配；会话不共享群组成员，且不能通过群组设置扩展参与者。侧栏与 Bot 页面可随时打开同一聊天。

`010_bot_coordinators.sql` 新增主会话、幂等工具调用、来源记忆、任务执行选择和逐次 Worker 记录，移除旧的每 Bot 单执行索引；并发限制和资源协调改由持久状态与调度器共同执行。`011_empty_start.sql` 仅移除未经使用的旧默认群，不会删除其中已有 Bot、消息、任务或会话记录。

数字员工对话模型可在运行时更换；OpenAI-compatible 服务使用 Chat Completions 与工具调用，Anthropic 使用原生 Messages 和 tool_use/tool_result。API Key 在服务端以 `0600` 权限保存到 `model-settings.json`，不进入快照或模型上下文。群对话上下文分别标注人类所有者与 Bot 身份。单次模型失败保留该收件箱事件，可在对应的来源消息下单独重试，不重复已完成的其他 Bot 回复。`012_bot_attention.sql` 新增持久注意力判断与独立 Bot 唤醒计数，升级保留现有身份、记忆、消息、任务与原生会话。
